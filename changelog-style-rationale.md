# changelog-style rationale — per-rule history and provenance

This file is Tier 3 rationale for rules whose canonical text lives in `kernel-style.md` §0 and `changelog-style.md` §1-§3. Each rule has stable ID matching hot files per CONTRIBUTING §9, so CI can check for orphan IDs.

Rationale is public-audience: Message-IDs, public reviewer names, commit hashes, alternative phrasings considered/rejected. No internal identifiers.

## R0 — Factual integrity (canonical: kernel-style.md §0)

- <!-- R0-1 --> Never invent — derived from maintainer edits of AI drafts in 2026-07 where numbers and hashes were hallucinated. Real examples: fabricated benchmark deltas in get_user_page_vma draft, invented Fixes: hashes not in `git log`. Enforcement: `git show <hash>`, paste verbatim.

- <!-- R0-2 --> If you don't know, TODO — pattern from Breno Leitao style: honest doubt "I _think_..." preferred over plausible fill. Trust breach vs recoverable gap.

- <!-- R0-3 --> Verify every claim against diff — standard kernel practice, but LLMs skip. Derived from changelog-style.md verification gate. See also `scripts/lint-changelog.py` checks scope.

- <!-- R0-4 --> Cover letter is claim against every patch — from real bug 2026-08-01 where gup cover letter had 2721/1198/2.3x vs patch actual 2801/1188/2.4x (stale after rebase). Found by hand, missed by old `verify-cover-letter.py` which only checked Before:/After: shape presence, not number diffing. Fixed to diff values per unit. See also patch-series.md §5.

- <!-- R0-5 --> Paste raw artifact verbatim — Dan Williams `101c268bd2f3` annotated splat with 1)2)3) markers; Mel Gorman `09a913a7a947` benchmark table; Breno Leitao `62adf8c290f2` time before/after. Rule: paste literal block then explain.

- <!-- R0-6 --> Treat unverified prose as bug — enforced via `/kreview` gate, checkpatch.pl, lint-changelog.py.

- <!-- R0-7 --> Carried-forward text is re-asserted — from forward-porting a long mm series onto a newer base in 2026-08. Two independent failures, both inherited rather than invented: a changelog kept "zero WARN/BUG" stress figures and a "~14 hours bare-metal" claim measured on the *old* base, and a bugfix changelog described a `list_del` corruption splat that the author had never reproduced, both restated verbatim under the porting author's name. The 14-hour run had in fact missed a preempt-count underflow later found in that same code, so the retained claim was not merely stale but misleading. R0-1 ("never invent") did not fire because nothing was invented — the gap was that re-asserting someone else's unverified claim is indistinguishable, to a reader, from making it yourself. Enforcement: treat every retained sentence in a rewritten changelog as newly written for R0-8 purposes.

- <!-- R0-9 --> An explanation is a claim — added after R0-1/R0-5/R0-7/R0-8 all failed to catch two wrong sentences in one small mm changelog in 2026-08. First: "that zone id is *simply* the last zone processed in memmap_init()'s iteration", true of one of the two call sites and false of the other, which passes the zone whose memory follows the hole; the sentence also framed long-documented deliberate behaviour as an oversight. Second: "e.g. a hole between DMA32 and Normal", describing a gap between zones, which cannot exist — zones tile PFN space contiguously (checkable in `/proc/zoneinfo`: each zone's start_pfn equals the previous zone's start_pfn plus its spanned pages). Neither is a number, hash, splat or benchmark, so every existing factual-integrity rule was shaped for the wrong target. Both were confident prose *about* code, written from the author's model of it rather than read off it. Detection signal: names code AND states it absolutely. Measured 30 of 293 sentences (10%) over a 40-patch series, roughly one per changelog, and flags both failures above. Caveat for future editors: that heuristic was tuned knowing the two failures it had to catch, so the rate is optimistic until validated on an unrelated series. The lint cannot judge truth; its value is forcing enumeration, which is the step that was skipped — the same reason R0-8's claims table worked.

- <!-- R0-8 --> Name the artifact per claim — companion mechanical step for R0-1/R0-3/R0-7. Same 2026-08 series: `checkpatch.pl` reported "no obvious style problems and is ready for submission" on a patch whose changelog asserted an unobserved splat, so the existing tool gate gave false assurance. Listing each empirical claim beside the artifact that produced it (log path, command output, `git show` hash) is checkable by a reviewer and by the author, where "did I verify this?" recalled from memory is not.

- <!-- R0-3-CH --> Changelog-specific verification of scope/files/symptom/cause/fix/perf/Fixes/Link/Reported-by — subset of R0-3 focused on changelog. Derived-not-measured clause added 2026-08-17: a draft claimed maple nodes cost "roughly 28-41 bytes per entry at typical fill", computed from node-fill assumptions rather than measured. The author deleted it instead of defending it. The point is not that the estimate was wrong. A number derived from assumptions cannot be checked by a reviewer, so it buys nothing that omitting it would not.

- <!-- R0-5-CH --> Artifact verbatim checks: git show exists, lore/syzbot link resolves.

- <!-- R0-6-CH --> Pre-write gate tools: /kreview setup (review-prompts.md), checkpatch.pl, git log, benchmark, lint-changelog.py.

## CL-10 — Subject line

- <!-- CL-10 --> `subsystem: lowercase imperative` — from submitting-patches.rst. Examples `1aa43598c03b` "mm: remove unnecessary calls...", `434247637c66` "bpf: use kvzmalloc...". x86/tip exception `209954cbc7d0` capitalizes first word — match subsystem's existing style, not fixed rule. Mechanically checkable: no trailing period.

- <!-- CL-10b --> Check git history prevailing prefix — `kernel/trace/fprobe.c` uses `tracing/fprobe:` not `trace/fprobe:` (historical precedent). Run `git log --oneline -- <path>`.

- <!-- CL-10c --> Comma-joined multi-subsystem prefixes `mm,vmscan:` — common habit e.g. `8ebe0a5eaaeb`, `da27f796a832`, no space after commas.

- <!-- CL-10d --> Subject must reflect primary impact, not cleanup label. From lore week 2026-07-28..08-04: wifi brcm80211 performance and stability fixes, Arend van Spriel `<d5b7a4a8-532f-47c7-a883-036d5cc81a90@broadcom.com>` review: frame lost when count zero "silently, so frame is lost rather than retried... this change is primarily potential bug fix so rephrase subject, e.g. fix blocked-ring race permanently stopping queue". Also same thread flagged LLM lingo "if coding assistant used please disclose it" — don't hide bugfix as cleanup, and don't hide assistance. Existing CL-10 says lowercase imperative but not that subject must not use meta-verb "Fix <action>" that garbles nor cleanup label that hides impact. Example before "track credits" after "fix blocked-ring race stopping queue". Checkable: if body describes queue stop/data loss/race but subject says "cleanup" or "track", flag.

- <!-- CL-10e --> Prefer positive behaviour naming over negative removal naming when positive exists. Motivation: subject read in shortlog beside neighbours, where "do not answer a different question than --git asked" tells what stopped and "honour --git on an index older than this build" tells what now works — second same patch same length, more informative. Test that decides: can you name behaviour after patch in about same words? If yes, that is subject. Negative form earns place when removed behaviour *is* the point and no positive names it — leak, spurious warning, write that should never have happened (`drbd: don't leak the shared secret to unprivileged netlink dumps` has no better positive form, `iomap: don't free integrity payload that doesn't exist`). Preference not ban: measured 1,840 of last 100,000 upstream subjects use "don't" or "do not" (2026-08), sampled all of that kind. Enforcement: `lint-changelog.py` prints note never violation, because whether positive form exists needs diff and check firing on 2.1% of correct upstream subjects would teach skimming.

- <!-- CL-10f --> Sample the touched file's history for body idiom, not just the subject prefix. CL-10b stops at the `subsystem:` token; the body carries the same per-subsystem conventions — terminology, length, tone — that a foreign draft misses the same way `trace/fprobe:` would. Motivation: LLM changelogs read with correct grammar but the wrong vocabulary ("block" where the subsystem says "gigablock", generic sentences where the file's history is terse); close reading by maintainers flags it as not-native even when every claim checks out. `90d79f4b97e9` is the positive corpus anchor: its body walks in the names its own diff introduces (`PB_has_kernel`, `nr_content_blocks`, `gigablock`) across six tight paragraphs — the rule to hold a draft against. Sampling constraint: commits by different authors, and never only the current series' own patches — patch 10 of a 12-patch series whose `git log` window is patches 2, 3, and 5 calibrates the draft against the series' own prose, so if that prose was LLM-written the check validates the draft against itself and reports native. Where a file's history is single-maintainer, older pre-series commits serve; the invariant is that the sample exclude the idiom being drafted. Not mechanically checkable (terminology fit needs the diff and a judgement), so prose only, consistent with CL-10e's enforcement choice. Added 2026-09-23. Sample-size refinement, same date: two or three samples are calibrated for the low-variance dimensions — vocabulary, tone, prefix are near-categorical (two different authors writing `gigablock` settle the term; there is no distribution to sample), which is exactly what sampling is for. Length is the exception: continuous, high-variance, and confounded with change kind — three samples whose window happens to hold doc tweaks under-read a file whose race fixes run six paragraphs, so a draft calibrated on them lands outside the file's real envelope. Different authors remove the between-author variance, not the change-size variance, which is the larger one; hence the split: samples learn the dialect, length is measured against the file's distribution (`git log --format=%B -20 -- <path>`) with one sample of similar size and kind as the CL-24 calibration point. Residual failure mode is the transitional file — rename or folio-style conversion in progress — where two samples can confidently pick the dying term; samples that disagree with each other are the signal to sample up, not to average.

## CL-11 — Fixes + Cc: stable pairing

- <!-- CL-11 --> If Fixes: footer, add Cc: stable@vger.kernel.org — Fixes: marks bug worth backporting. Checkable: Fixes present but no Cc stable is red flag. Enforced by `scripts/lint-changelog.py`.

## CL-12 — Paragraph caps

- <!-- CL-12 --> At most one paragraph over 50w, none over 70 — was "90% of paragraphs ≤50w", changed 2026-08 after applying it to a 40-patch series. A percentage reads lenient but is severe on short changelogs: at 5 paragraphs, 4/5 = 80% < 90%, so *zero* paragraphs could exceed 50 words, and most changelogs in that series are 3-6 paragraphs. The intent was one idea per paragraph with a little slack for content that will not split; an absolute count expresses that directly and does not tighten as the changelog gets shorter. Hard 70 unchanged. — checkable backstop for "one idea per paragraph" from kernel-readability-principles. Applies to changelogs and code comments. Enforced by lint-changelog.py. Cutting >70 signals to split or compress, not pad to 70. Merging two related clauses under cap beats splitting for "one idea per paragraph" cost. Precedence over "one idea per paragraph" split out to CL-12b 2026-08-17.

## CL-14 — Audience / internal identifiers

- <!-- CL-14 --> No internal identifiers — agent/bot nicknames, private syzkaller bucket hashes without public syzbot link, internal branch names, private hostnames, build IDs, vendor ticket IDs, Phabricator/Jira IDs. Upstream reviewers lack context; reads as noise. Use generic "syzkaller triggers", "KASAN reports", "tested on v6.15-rc1". Provenance in trailers (Reported-by, Link) not prose. Extends to code comments: no dashboards in `/* */`. Public LKML reviewer names (Hildenbrand, Gleixner, etc.) are fine — public participants with lore archives. Internal-only attributions belong in trailers or private notes only. See also CONTRIBUTING §4 external-facing discipline, flock-norms #10. Example cut: "analyzed by internal-agent-1" → "syzkaller triggers..".

- <!-- CL-14-CH --> Audience rule changelog-specific — same as CL-14 but emphasizes changelog body must make sense to external reviewer with zero internal context.

- <!-- CC-14 --> Same rule for code comments — even less context allowed in source than changelog.

## CL-20..28 — Changelog body structure

- <!-- CL-20 --> Open with problem in present tense — universal from 14 developers. Never "This patch". Example `e9868505987a`. Validated against llm-tells checklist.

- <!-- CL-21 --> Keep verb tense consistent — present throughout. Mixing tenses makes reviewer unsure whether current behavior or history. Validation 2026-07-01 David Hildenbrand review.

- <!-- CL-22 --> Lead bugfix with real-world symptom — who triggers, what breaks, then internals. Example `2820b0f09be9` opens with jemalloc/tcalloc → SIGBUS, not "zap_page_range_single fails to take i_mmap_rwsem".

- <!-- CL-46 --> Keep the impact, with few numbers. Marked experimental (2026-11-27): sourced from rtmutex review practice (Desnoyers 2026-11-08), so there is no citable upstream hash and none should be invented. Reassess 2027-02-27 — replace with a merged-commit citation if the pattern appears in reviewed LKML history, or drop. One sentence and one figure per effect; stable maintainers and backporters need it to judge backport worth. Kept even when a reviewer's own rewrite drops it — Mathieu Desnoyers kept the impact paragraph Steven Rostedt's rewrite had cut (Steven is a native speaker; many readers are not, and the impact sentence orients them before the mechanism).

- <!-- CL-23 --> For race, draw CPU 1 / CPU 2 ASCII ladder — common device, e.g. `2820b0f09be9`. Partner-tagged barriers for Zijlstra. Refined 2026-11-27 from rtmutex review practice: Zijlstra called the v1 message "word soup" (2026-11-07) and Rostedt "very verbose ... makes it sound more complicated than it is"; Desnoyers review concluded a diagram only earns its place when step order between actors is the bug (a single-loop missed exit check was "overkill"), the legend names every actor/CPU/lock first, and setup runs as a step rather than implicit initial state. Width: diagrams may run to 100 columns, accepting checkpatch's "Prefer a maximum 75 chars per line" (verified in the reviewed tree's scripts/checkpatch.pl); precedent `b6e13e85829f` ("sched/core: Fix ttwu() race", verified via git show, max body line 92).

- <!-- CL-24 --> Match changelog length to change size — simple improvement ~3 paragraphs (efa7df3e3bb5), race earns more.

- <!-- CL-25 --> Structure problem→cause→fix→effect, 3-6 paragraphs 2-4 sentences each — typical shape `5cbcb62dddf5`.

- <!-- CL-48 --> A feature message runs need → design → API → tests. Marked experimental (2026-11-27): sourced from rtmutex review practice, adapted for features per Desnoyers on rcu_txn v2 (2026-11-10), so there is no citable upstream hash and none should be invented. Reassess 2027-02-27 — replace with a merged-commit citation if the pattern appears in reviewed LKML history, or drop. CL-25's shape is fix-shaped (problem, missed case, fix); a feature has no bug impact to keep and no "Fix this by ...". The four stations stand in the same order a reviewer asks: why does this exist, how does it work, what do I call, how was it tested.

- <!-- CL-26 --> Explain WHY with data — before/after tables, percentages. Examples `e1e4cfd01a6e` 1560→4720 MB/s, `209954cbc7d0` 4.5s→4.2s, `da27f796a832` 6 min→1 sec. Removal-by-benefit clause added 2026-08-17, folded in from a proposed standalone rule: "the slab cache no longer needs SLAB_HWCACHE_ALIGN, which had rounded each iova up to 64" became "Remove SLAB_HWCACHE_ALIGN to pack 4 iova structs in a cache line" — shorter, and checkable against the 16-byte struct the same paragraph states. Marked experimental (2026-08-17), same basis as CL-35..CL-37 below.

- <!-- CL-26b --> More about motivations than implementation details. Lead with why old behavior was costly — user-visible symptom, spec violation, regression, risk — not how you fixed it. From lore week 2026-07-28..08-04: Jakub Kicinski `<20260803230745.2291141-2-kuba@kernel.org>` hinic3 old code sent frame with pseudo-header checksum only → changelog must describe wire corruption, not internal flag `ip_summed stays CHECKSUM_PARTIAL`; Alison Schofield cxl `<anFCdsSo6dvxfFrZ@aschofie-mobl2.lan>`: implied partition order — define what order is, where from spec, that patch starts enforcing. Same principle that cut meta verification paragraphs with tool names and internal review nicknames per CL-14 in this repo's own history — motivation (wire corruption, spec violation) > mechanism (which helper, which lock). Design-tradeoff clause added 2026-08-17, folded in from a proposed standalone rule: an alignment paragraph reading "requesting size + alignment - 1 pfns, which leaves room to round up inside the range that comes back" was replaced by "rounding up the allocation size, prioritizing speed over address space waste, with the thought that many iova requests on a system will be similar in size, and reuse the same holes". Same length; the second names a cost and an assumption a reviewer can disagree with. Marked experimental (2026-08-17), same basis as CL-35..CL-37 below.

- <!-- CL-27 --> Paste raw artifact verbatim — KASAN splat, benchmark table indented as literal block. Composite: Dan Williams `101c268bd2f3` annotated splat.

- <!-- CL-28 --> If bug produces kernel message, MUST include verbatim — KASAN/UBSAN/WARNING/oops/Call Trace indented literal block, not paraphrase. Trim noise but keep signature, Call Trace, Allocated-by/Freed-by for UAF. Never fabricate matching splat if you captured different signature (R0).

- <!-- CL-44 --> State design intent before missed case. From rtmutex review practice (Zijlstra "word soup" 2026-11-07; Rostedt "very verbose ... makes it sound more complicated than it is"; Desnoyers 2026-11-07/08): a fix for a gap in assumed behavior first states why the code is built that way, then the case it missed, so the fix reads as the obvious one. The Fixes commit's own changelog usually states the intent — `992caf7f1724` ("Going to sleep when locks are contended can be quite inefficient when the contention time is short...", verified via git show) states why the spin exists. Corrollary: never invent intent the commit, its comments, or its author do not state.

- <!-- CL-29 --> Write for human reviewers: narrative with transition phrasing, not semcode dump. Cite only 2-3 key file:function needed for kverify, not every line. One idea per paragraph. At paragraph boundary where state changes, use explicit transition naming actor/event first: "When X is changed from A to B, ..." rather than dense "from previous X mode, while current Y...". Derived from personal style rule saved in memory and from redrat3 UAF fix where old changelog had file:line every sentence (at redrat3.c:1023, at 935, at 941, at 942, at 958, in 971, in 924, etc.) reading like kverify dump, not story. That slipped through because kernel-style.md only checks subject (CL-10) and changelog-style.md had no density limit. Human-friendly version cuts to 2-3 cites and uses transition "When the detector enable fails after the RC device is registered, the probe jumps to..." naming actor/event first per CL-12.

- <!-- CL-30 --> Safety paragraph for concurrency/locking/bounds fixes: must state "should be safe because..." not "is safe because...", naming protecting lock/snapshot and why no new race. Verifiable in review — reviewer checks lock, snapshot, free path you name. Derived from real syzkaller fixes: nvmet max_qid fix `eae699c90e4b`→`deb91776540e` transition — configfs qid_max store holds down_write(&nvmet_config_sem) deletes old controllers, snapshot in ctrl immutable after creation, no extra locking should be needed. Pattern in fbdev bitblit fix `bb46c1e199cc`.

- <!-- CL-61 --> Restoration needs no safety case. Marked experimental (2026-11-27): ported from commit-voice V14, no merged-commit corpus. Reassess 2027-02-27. Dual of CL-30: that rule demands a safety argument for new behavior, this one forbids the cargo-cult paragraph on a restoration. A safety section on behavior that shipped for years reads as the author doubting the history — and invites the reviewer to doubt it too.

- <!-- CL-31 --> Chain-of-events paragraph mandatory for every syzkaller fix, 2-4 sentences, file:function per step, sister-site contrast, concrete OOB example. Derived from syzkaller workflow needing to verify bug possibility without reproducer. Examples: fbdev soft_cursor global OOB — When font is changed from 512 to 256 glyphs, hi_font_mask cleared but screen buffer retains high-bit glyph via vt.c:screen_glyph, bit_cursor lacks clamp vs bit_putcs_aligned at 18c4ef4e765a which does clamp, concrete glyph 257 past 256-glyph fontdata_8x16+0x1010; nvmet TOCTOU — When max_qid raised from small to large via configfs.c:attr_qid_max_store under down_write, controller keeps old small sqs array allocated in core.c:nvmet_alloc_ctrl, I/O connect validates against new large but dereferences old array at qid=2 past 16-byte. Keep under 70 words, one over-50 allowed, kverify checks file:function exists and sister-site has clamp.

- <!-- CL-54 --> Open with the tripwire. Marked experimental (2026-11-27): ported from changelog-quality GC-21, no merged-commit corpus. Reassess 2027-02-27. A mechanism paragraph that walks the whole path before naming the gate buries the one line the safety claim rests on; opening with the flag combination plus the dead-code consequence inverts the burden — the reviewer verifies the gate fires rather than auditing a path that never runs for the affected class.

- <!-- CL-55 --> Say which stage a check gates. Marked experimental (2026-11-27): ported from changelog-quality GC-25, no merged-commit corpus. Reassess 2027-02-27. Permission and acquisition checks are stage-specific: a page vetted at lookup time can still be transformed before use, and a consumer-side recheck says nothing about what acquisition allowed through. "Does not need a check" without a stage invites the reader to extend the exemption to the stage the author never examined.

- <!-- CL-32 --> Per-patch benchmark attribution when a series splits one optimisation. Derived from mm/gup follow_page_mask batching, posted as a single combined table in `20260801031540.2742891-1-riel@surriel.com`: `4 kB 2721->1198 (2.3x), 64 kB mTHP 2929->201 (14.6x)`, all attributed to the final batching patch. Re-measured per patch with before held at the series base, the walk alone gave 4 kB 2753->1178 (2.3x) and 64 kB 2946->1361 (2.2x); batching then took 64 kB to 231 (12.8x). The walk helped both sizes about equally because what it saves is the page-table descent, not anything folio-specific — invisible in the combined number. CL-26/CL-27 require a table; neither requires attribution across a split.

  Table-shape note added 2026-11-27, ported from evidence-discipline GC-82. Marked experimental (2026-11-27), no merged-commit corpus. Reassess 2027-02-27. A comparison table whose axes or conditions shift per candidate silently accommodates shape failures — the reader compares numbers that were never measured the same way. Fixing the shape first turns a mismatch into a visible finding instead of a quiet accommodation.

- <!-- CL-52 --> State the math each path uses and which side diverged. Marked experimental (2026-11-27): ported from changelog-quality GC-13b, no merged-commit corpus. Reassess 2027-02-27. A divergence message that describes only the mismatch ("outputs differ") leaves the reviewer to bisect two implementations blind; naming each side's math plus the convicted side reduces the audit to one path. Companion to CL-32: that rule attributes effects across patches, this one attributes divergence across paths within a patch.

- <!-- CL-53 --> Results are a setup sentence plus a table. Marked experimental (2026-11-27): ported from commit-voice V35 with changelog-quality GC-15d/GC-17c, no merged-commit corpus. Reassess 2027-02-27. A prose list of rates cannot be scanned against anything, so any paragraph that reads as numbers-in-sentences becomes setup-plus-table. The setup names workload, hardware, and tier sizes; everything else is cells. External-names discipline is the same demand as CL-14 applied to the results section: internal hosts, paths, and script names mean nothing to a reviewer who never ran the rig — and neither do rig-phase labels, which name the author's procedure instead of the measured thing.

- <!-- CL-33 --> Within-noise differences and control rows. From the mm/gup per-patch re-measurement: 4 kB base pages read 1178 us with the walk applied and 1198 us with batching applied on top, across two boots of the same benchmark. Batching cannot touch base pages, which share no folio, so the 1.7% is variation; reporting it either way would have invented a mechanism. The 2 MB THP row stayed at 70-72 us throughout and is what demonstrates follow_page_pte() is never reached for PMD-mapped folios, a scope claim otherwise unverifiable from the changelog.

- <!-- CL-65 --> Post-gate counts name the gate. Marked experimental (2026-11-27): ported from commit-voice V49, no merged-commit corpus. Reassess 2027-02-27. The reader's default model is uniform sensitivity: every fault counted, every page equally suspect. A count taken downstream of a per-page gate violates that model silently, and the gap between the count and the total reads as sloppiness rather than design. Naming the gate restores the model — the excluded members were vetted elsewhere, and the count covers exactly the remainder.

- <!-- CL-50 --> Specify the re-run, never apologize for the gap. Marked experimental (2026-11-27): ported from changelog-quality GC-15c, no merged-commit corpus, so there is no citable upstream hash and none should be invented. Reassess 2027-02-27. A message that says "numbers to be confirmed" strands the reviewer: confirm how, on what, and the sentence is unnecessary. The re-run spec names the command, the tree, and the config, turning a caveat into a queued check a reviewer can execute or waive explicitly.

- <!-- CL-51 --> A clipped run is a lower bound, never a value. Marked experimental (2026-11-27): ported from evidence-discipline GC-66, no merged-commit corpus, so there is no citable upstream hash and none should be invented. Reassess 2027-02-27. The failure mode is a message reporting the point of interruption as the result — a timeout at 300s reported as "takes 300s", a clipped log's last line as the outcome. The fix is mechanical: every number carries the run's completion state, and an incomplete run degrades to "at least" or disappears.

- <!-- CL-45 --> Say what bounds a number, not just its value. Marked experimental (2026-11-27): sourced from rtmutex review practice (Desnoyers 2026-11-07/08), so there is no citable upstream hash and none should be invented. Reassess 2027-02-27 — replace with a merged-commit citation if the pattern appears in reviewed LKML history, or drop. A "maximum seen in testing" is not a limit: the PREEMPT_RT ww_mutex spin's "up to a second" was the fair server (950ms default period plus runtime) — moving those settings moved the maximum exactly, and with the fair server off the spin ended on the 4s softlockup-watchdog period. The message now says what stops the spin, not how long it lasted in our runs.

## CC-10..14 / CS-10..15 — Code

- <!-- CC-10 --> Comment WHY not WHAT — hardware, locking, ordering, lifetime. Universal.

- <!-- CC-10b --> Restatement that reads like explanation. CC-10 bans restating the code, but a comment can describe what a function does with its arguments and still feel like a why, because it names a purpose rather than echoing a line. Two from one review of a maple tree helper:

  Before: "Widen [*lo, *hi] to cover every iova overlapping the requested range, or return the existing iova if that one already covers the whole request." After: "A maple tree cannot hold overlapping ranges, so overlapping reservations have to be merged into one wider entry." The before is the signature in prose; the after is the constraint that forced the helper to exist, and the rbtree version it replaced simply left overlapping nodes in the tree.

  Before: "Preallocate the nodes for the merged store so it cannot fail; only then free the now-superseded overlaps and store the merged range." After: "The superseded overlaps are freed before the merged store, so the store must not be able to fail after that point." Same length. The before spends its second clause listing the order of the next eight lines; the after says why the preallocate call is there at all.

  Both drafts passed a self-review against CC-10 because each explained *a* why — a purpose, an ordering. The narrower test is whether the sentence could be reconstructed from the signature plus the body. If it could, it is restatement.

  Marked experimental (2026-08-17): two instances, one helper, one author, no merged-commit corpus. Reassess 2026-11-17.

- <!-- CC-11 --> Density low purposeful 1-2 lines typical max 2-8 block, same 50w cap per CL-12.

- <!-- CC-12 --> Plain why-block or nothing on statics. The check predates the rule: scripts/lint-code.py already flags @param under a static as [CC-12], but no CC-12 existed in the docs — check-orphan-ids.py pairs hot files against rationale files, never the IDs a script emits, so the gate stayed green around a dangling pointer review.md cited too. Provenance: kernel-readability #12 (reserve /** for exported APIs) and the llm-tells-checklist scaffolding item. Enforced by this repo's own script.

- <!-- CS-10 --> Split out named helper when predicate multi-branch/reused — e.g. should_flush_tlb(). Decompose.
